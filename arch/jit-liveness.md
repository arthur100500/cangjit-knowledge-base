# JIT liveness

`LivenessAnalysis` computes block-level liveness once and returns a `Liveness` result containing packed live-value bitmaps for each CHIR expression and each block exit. A lookup maps each expression to its bitmap row: the row is liveness before the expression, and the next row in the same block is liveness after it. Block entry liveness is the first row, including the exit row for an empty block. This shares instruction-level liveness among interference construction, safepoint metadata generation, and debug output without repeated backward walks.

Bitmaps include both normal and exceptional successors. Safepoints still perform separate must-initialization, reference-provenance and GC-root classification; ordinary liveness alone cannot identify safe roots. CHIR blocks and expressions must remain alive and unchanged from analysis until the result is discarded after function compilation. A compact row per expression plus block exit uses more temporary memory than recomputing rows on demand, in exchange for reducing repeated work during JIT compilation.
