# How the x86-64 JIT metadata builder lays out runtime metadata

`src/JIT/Runtime/JitMetadataBuilder.{h,cpp}` records a frame, safepoints (GC roots, stack roots and derived roots), landing pads and call sites, then validates and encodes them in `Build`. It returns descriptor bytes plus a four-byte signed little-endian relative offset from the word immediately before the code entry to the descriptor. The descriptor must be four-byte aligned, in signed 32-bit range, and not overlap that word.

The descriptor starts with seven 32-bit words: stack-map offset, code size, name/directory/file string offsets, dictionary offset, and exception-table relative offset. Encoded trace strings and their dictionary follow; the bit-packed stack map follows those strings, then optional exception data. Stack-map rows contain PC and one-based indices into register-mask, frame-slot bitmap, line, derived-root, and (with stack growth enabled) stack-root tables. Zero means no row. The builder sorts safepoints, rejects duplicate PCs and invalid slots, and uses variable-width, least-significant-bit-first encoding; slot bitmaps describe eight-byte-spaced RBP offsets. For example, a safepoint with only a GC slot at RBP-16 has a nonzero slot-table index and a bitmap beginning at -16; an empty root set has index zero. Exception call-site entries map code ranges to landing pads and action/type records. This is an overview, not a substitute for the runtime's binary-format definitions.

`stackGrowth` is an assertion about the runtime mode, not a switch that enables growth. It controls stack-root columns needed when a stack moves; disabled mode rejects recorded stack roots. `GlobalContext::ConfigureRuntime` passes the same choice into builders, while `X86_64Compiler::ConfigureStackGrowth` obtains it from `cjStackGrow`. The host must match the runtime's mode; the code says there is no public query for it. The separate stack-overflow crash remains unresolved (`ai-issues/001-jit-stack-overflow.md`).
